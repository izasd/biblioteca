Biblioteca — uma feature, 53 fases

Você vai construir, do zero, uma API que faz duas coisas: cadastrar um livro e buscar um livro. Só isso. E vai levá-la, passo a passo, de um arquivo único com SQL dentro do handler HTTP até um monólito modular com DDD, Clean Architecture e fatias verticais — sem nunca acrescentar uma terceira funcionalidade.

O que vamos construir

Uma biblioteca precisa catalogar o acervo. A funcionalidade é uma só — Livros — e tem dois casos de uso: cadastrar um livro no acervo e procurar por ele. Não há empréstimo, não há leitor, não há devolução.

Essa limitação é deliberada. Como a largura do sistema está travada, tudo o que crescer no projeto cresceu por causa da arquitetura — e só por causa dela. Ao final das 53 fases você vai poder olhar para trás e apontar, para cada arquivo novo, exatamente qual dor o fez existir.

A conversa com o cliente

Todo requisito começa como uma frase dita por alguém que não programa. Esta é a transcrição do trecho que interessa:

“A gente cataloga o acervo à mão até hoje. O que eu preciso é simples: o bibliotecário digita o ISBN, o título e o autor, e o sistema fica com o resto. O número de registro quem dá é a casa — no formato do ano, em sequência —, e a data de catalogação é a data em que a ficha entrou, não a que a pessoa resolveu digitar.

Autor não se inventa aqui: a gente recebe a base de autoridades pronta, de fora. Se o nome não está lá, o livro não entra.

Ah, e tem uma política de aquisição: no máximo três livros do mesmo autor. Acervo não pode virar coleção pessoal de ninguém. Livro repetido também não — nem o mesmo ISBN, nem a mesma obra em outra edição.

Para procurar, o pessoal do balcão usa uma caixinha só. Às vezes tem o ISBN na mão, às vezes lembra meia palavra do título, às vezes só o sobrenome do autor.”

— Diretora da biblioteca, na reunião de levantamento

Repare em quantas regras estão escondidas nessas quatro falas — e em como nenhuma delas é um botão na tela. É essa distância entre o que o cliente disse e onde a regra vai morar no código que o percurso inteiro percorre.

bun init e estrutura de pastas

Você cria o esqueleto do projeto: um projeto Bun com TypeScript, a pasta src/ para o código e a pasta data/ para o banco. Nenhuma decisão de arquitetura ainda — só um programa que roda e imprime uma linha. É o ponto zero do percurso, e serve para todo mundo começar do mesmo lugar.

👨‍💻 O que você digita

Na sua branch uma-feature, a partir da raiz do repositório clonado:

terminal
bun init -y
rm -rf .cursor CLAUDE.md README.md
mkdir -p src data
mv index.ts src/index.ts
touch data/.gitkeep

O bun init -y já cria package.json, tsconfig.json e instala @types/bun e typescript. Não precisamos de mais nada — nem de servidor HTTP, nem de driver de banco.

Os arquivos abaixo são os que o Bun 1.4 gera. Versões anteriores (1.3.x) geram "typescript": "^5" e não incluem a linha "types": ["bun"] no tsconfig.json — se for o seu caso, acrescente a linha à mão: sem ela, o TypeScript 7 nativo (o tsgo que a IDE usa) não enxerga Bun, bun:sqlite nem bun:test.

O .gitignore já vem pronto na main e cobre node_modules/, o arquivo SQLite e os CSVs de importação. Detalhe que economiza confusão: o bun init preserva um .gitignore existente em vez de sobrescrevê-lo.

A pasta data/ vai guardar o arquivo SQLite, que não entra no versionamento; o .gitkeep existe só para o Git preservar a pasta vazia.

A base de autores entra por um seed

Requisitos: RF03, RF04

Você popula a tabela autores com quatro fichas por um seed. Note bem: a base de autores não é criada pela API. Ela é cópia de uma base externa e entra no sistema por fora. Parece burocracia agora; na fase 47 vira a fronteira entre dois módulos.

👨‍💻 O que você digita

Um array de constantes e um INSERT OR IGNORE, que torna o seed idempotente: rodar a aplicação dez vezes não duplica nada.

⚠️ Repare que o id vai explícito no INSERT. Sem ele, o OR IGNORE não teria conflito nenhum para ignorar — nome não é único — e cada bun run start acrescentaria mais quatro autores. Idempotência não vem do OR IGNORE; vem de existir uma chave que possa colidir.

Repare que nenhum dos quatro tem ORCID. Três morreram antes de o registro existir, e o quarto simplesmente não tem um. É exatamente por isso que a chave primária é o id — e é esse o assunto da fase 33.

src/db.ts — arquivo completo, com as mudanças marcadas

typescript
import { Database } from "bun:sqlite";

export const db = new Database("data/biblioteca.sqlite", { create: true });

db.run("PRAGMA foreign_keys = ON;");

// O id vai explícito de propósito: é ele que faz o INSERT OR IGNORE ser
// idempotente, e é ele que os exemplos deste documento referenciam.
// O ORCID é nulo para os quatro — três morreram antes de ele existir.
const AUTORES = [
  [1, "Eric Evans"],
  [2, "Robert C. Martin"],
  [3, "Harper Lee"],
  [4, "Jane Austen"],
] as const;

function seedAutores() {
  const insert = db.prepare(
    "INSERT OR IGNORE INTO autores (id, nome) VALUES (?, ?)",
  );

  for (const [id, nome] of AUTORES) {
    insert.run(id, nome);
  }
}

export function createDb() {
  db.run(`
    CREATE TABLE IF NOT EXISTS autores (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      nome TEXT NOT NULL,
      orcid TEXT UNIQUE
    );
  `);

  seedAutores();

  console.log("Banco de dados inicializado.");
}

Tabela livros, com chave estrangeira

Requisitos: RF01

Você cria a tabela livros, com chave estrangeira apontando para autores — a mesma que vamos remover de propósito na fase 50. O campo isbn nasce UNIQUE: é o que sustenta o RF08 e é a única regra deste sistema que o banco consegue impor sozinho.

👨‍💻 O que você digita

Note os dois UNIQUE, e que eles são de naturezas diferentes.

numero_registro é a identidade que a biblioteca grava na etiqueta: nós a atribuímos, sequencialmente, a partir da fase 15.

isbn vem de fora e apenas conferimos: é ele que vai sustentar o RF08 na fase 16 — e é ele que vai salvar o sistema da corrida entre o SELECT e o INSERT que aquela fase expõe.

Servidor HTTP com Bun.serve

Você sobe um servidor HTTP com Bun.serve, sem framework nenhum: responde a GET / e devolve 404 no resto. Zero dependências — e vai continuar assim até a fase 45. Escrever o HTTP na mão agora é o que vai permitir, lá adiante, medir exatamente quanto custa trocá-lo.

👨‍💻 O que você digita

Bun.serve() é o servidor HTTP nativo do runtime — não instalamos Express nem Hono. A função fetch recebe uma Request e devolve uma Response: é a mesma API do navegador.

Roteador manual com captura de parâmetros

Antes de escrever qualquer if (url.pathname === ...), você constrói um roteador de trinta linhas que casa método e padrão de caminho e captura parâmetros como o :q da busca. Trinta linhas que vão sobreviver até a fase 45 sem uma alteração sequer.

👨‍💻 O que você digita

Sem roteador, cada endpoint vira um if no fetch — e os que têm parâmetro ficam impossíveis: /livros/9780321125217, /livros/Clean e /livros/Austen são caminhos diferentes que precisam cair no mesmo handler. Comparar string com === não resolve.

São três peças: o tipo Route, a função match e o laço dentro do fetch.

A rota
typescript
type Route = { method: string; pattern: string; handler: Handler };

Método, padrão e o que fazer. O pattern é a única sintaxe que estamos inventando: segmentos literais (livros) e segmentos-variável, marcados com dois-pontos (:id).

match, linha a linha

Ela recebe um padrão e um caminho concreto, e devolve os parâmetros capturados — ou null quando não bate.

typescript
const patternParts = pattern.split("/").filter(Boolean);
const pathParts = path.split("/").filter(Boolean);

"/livros/".split("/") devolve ["", "livros", ""]: a barra inicial e a final produzem strings vazias. O .filter(Boolean) descarta tudo que é falsy, então sobra ["livros"]. Essa única chamada resolve de graça três casos que dariam bug — barra inicial, barra final e barras duplicadas.

typescript
if (patternParts.length !== pathParts.length) return null;

Saída barata, e é o que garante que /livros/:q (dois segmentos) nunca colida com /livros (um) nem com um futuro /livros/:isbn/edicoes (três). Sem essa linha, seria preciso inventar regras de precedência entre rotas — e num sistema onde POST /livros e GET /livros/:q dividem o mesmo prefixo, isso apareceria já na fase 10.

typescript
if (expected.startsWith(":")) {
  params[expected.slice(1)] = received; // ":id" vira a chave "id"
} else if (expected !== received) {
  return null; // literal que não bateu
}

Segmento com : captura o que veio; sem :, tem que ser igual. O slice(1) apenas corta os dois-pontos.

A sutileza que engana

match devolve null para "não bateu" e um objeto para "bateu" — inclusive {} quando a rota não tem parâmetro nenhum. Em JavaScript {} é truthy e null é falsy, então o if do laço distingue os dois casos:

typescript
const params = match(route.pattern, url.pathname);
if (params) return await route.handler(request, params);

Isso é frágil de um jeito instrutivo: trocar por if (params && Object.keys(params).length > 0) parece mais explícito e quebra a rota /, que casa com zero parâmetros.

Por que os !

O tsconfig do Bun liga noUncheckedIndexedAccess, então patternParts[i] tem tipo string | undefined mesmo dentro de um laço limitado por .length — o compilador não consegue provar que o índice é válido. O ! é você afirmando que sabe.

A rota descartável

/eco/:mensagem existe só para provarmos a captura de parâmetros antes de existir qualquer rota real com parâmetro. Ela some na fase 10.

type Handler = (
  request: Request,
  params: Record<string, string>,
) => Response | Promise<Response>;

type Route = { method: string; pattern: string; handler: Handler };

function match(pattern: string, path: string): Record<string, string> | null {
  const patternParts = pattern.split("/").filter(Boolean);
  const pathParts = path.split("/").filter(Boolean);

  if (patternParts.length !== pathParts.length) return null;

  const params: Record<string, string> = {};

  for (let i = 0; i < patternParts.length; i++) {
    const expected = patternParts[i]!;
    const received = pathParts[i]!;

    if (expected.startsWith(":")) {
      params[expected.slice(1)] = received;
    } else if (expected !== received) {
      return null;
    }
  }

  return params;
}

export type Handler = (
  request: Request,
  params: Record<string, string>,
) => Response | Promise<Response>;

export type Route = { method: string; pattern: string; handler: Handler };

export function match(
  pattern: string,
  path: string,
): Record<string, string> | null {
  const patternParts = pattern.split("/").filter(Boolean);
  const pathParts = path.split("/").filter(Boolean);

  if (patternParts.length !== pathParts.length) return null;

  const params: Record<string, string> = {};

  for (let i = 0; i < patternParts.length; i++) {
    const expected = patternParts[i]!;
    const received = pathParts[i]!;

    if (expected.startsWith(":")) {
      params[expected.slice(1)] = received;
    } else if (expected !== received) {
      return null;
    }
  }

  return params;
}

import { db } from "../db";

export type ResultadoDeLivro =
  | { ok: true; livro: unknown }
  | { ok: false; error: string; status: number };

export function cadastrarLivro(
  isbnBruto: string,
  titulo: string,
  autorId: number,
): ResultadoDeLivro {
  const isbn = isbnBruto.replace(/[^0-9]/g, "");

  const autor = db.query("SELECT * FROM autores WHERE id = ?").get(autorId) as
    | { id: number; nome: string; orcid: string | null; tipo: string }
    | null;

  if (!autor) {
    return { ok: false, error: "Autor não cadastrado", status: 404 };
  }

  const livrosDoAutor = db
    .query("SELECT COUNT(*) AS total FROM livros WHERE autor_id = ?")
    .get(autorId) as { total: number };

  const noAcervo = livrosDoAutor.total;
  const limite = autor.tipo === "didatico" ? 10 : 5;

  if (noAcervo >= limite) {
    return {
      ok: false,
      error: `O autor já tem ${limite} livros no acervo`,
      status: 409,
    };
  }

  const jaExiste = db.query("SELECT 1 FROM livros WHERE isbn = ?").get(isbn);

  if (jaExiste) {
    return { ok: false, error: "Livro já cadastrado", status: 409 };
  }

  const mesmoTitulo = db
    .query(
      "SELECT 1 FROM livros WHERE autor_id = ? AND lower(titulo) = lower(?)",
    )
    .get(autorId, titulo);

  if (mesmoTitulo) {
    return {
      ok: false,
      error: "Este autor já tem um livro com este título",
      status: 409,
    };
  }

  const hoje = new Date().toISOString().slice(0, 10);
  const ano = hoje.slice(0, 4);

  const catalogadosNoAno = db
    .query(
      `SELECT COUNT(*) AS total FROM livros
        WHERE data_catalogacao LIKE ?`,
    )
    .get(`${ano}%`) as { total: number };

  const numeroRegistro = `${ano}-${String(catalogadosNoAno.total + 1).padStart(6, "0")}`;

  const result = db.run(
    `INSERT INTO livros (numero_registro, isbn, titulo, autor_id, data_catalogacao)
     VALUES (?, ?, ?, ?, ?)`,
    [numeroRegistro, isbn, titulo, autorId, hoje],
  );

  const livro = db
    .query("SELECT * FROM livros WHERE id = ?")
    .get(Number(result.lastInsertRowid)) as Record<string, unknown>;

  return {
    ok: true,
    livro: { ...livro, autor: autor.nome },
  };
}

Você acaba com o (await request.json()) as {...}, que é uma mentira tipada — nada garante que o corpo tenha aquele formato. Nasce um lugar único para validar entrada e uma exceção InvalidInput para quando ela não bate. Por enquanto, ninguém captura essa exceção. É de propósito.

export class InvalidInput extends Error {
  constructor(message: string) {
    super(message);
    this.name = "InvalidInput";
  }
}

function asObject(body: unknown): Record<string, unknown> {
  if (typeof body !== "object" || body === null) {
    throw new InvalidInput("o corpo da requisição deve ser um objeto JSON");
  }

  return body as Record<string, unknown>;
}

function text(body: Record<string, unknown>, field: string): string {
  const value = body[field];

  if (typeof value !== "string" || value.trim() === "") {
    throw new InvalidInput(`campo obrigatório: ${field}`);
  }

  return value.trim();
}

function positiveInt(body: Record<string, unknown>, field: string): number {
  const value = Number(body[field]);

  if (!Number.isInteger(value) || value <= 0) {
    throw new InvalidInput(`campo inválido: ${field}`);
  }

  return value;
}

  isbn: string;
  titulo: string;
  autorId: number;

  const data = asObject(body);

  return {
    isbn: text(data, "isbn"),
    titulo: text(data, "titulo"),
    autorId: positiveInt(data, "autorId"),
  };
}

export function parseBusca(params: Record<string, string>): string {
  return text(params, "q");
}

Você separa em definitivo o que deu errado, que é vocabulário do sistema, de que número o HTTP usa para isso, que é vocabulário do transporte. Nasce a hierarquia ApplicationError e um único ponto que traduz exceção em status — e, de quebra, as rotas emagrecem à metade.

export class Isbn {
  readonly value: string;

  constructor(raw: string) {
    if (!Isbn.isValid(raw)) {
      throw new InvalidValue(`ISBN inválido: ${raw}`);
    }

    this.value = raw.replace(/[^0-9]/g, "");
  }

  /**
   * Perguntar antes de construir. Quem cadastra **exige** um ISBN; quem busca
   * apenas quer saber se o termo digitado é um — "Clean Code" não é, e nem por
   * isso a busca falhou.
   */
  static isValid(raw: string): boolean {
    const normalized = raw.replace(/[^0-9]/g, "");

    return normalized.length === 13 && Isbn.digitoConfere(normalized);
  }

  /**
   * ISBN-13: soma dos 12 primeiros dígitos com pesos 1 e 3 alternados;
   * o 13º dígito é o que completa a soma até o próximo múltiplo de 10.
   */
  private static digitoConfere(isbn: string): boolean {
    let soma = 0;

    for (let i = 0; i < 12; i++) {
      soma += Number(isbn[i]!) * (i % 2 === 0 ? 1 : 3);
    }

    return (10 - (soma % 10)) % 10 === Number(isbn[12]!);
  }

  equals(other: Isbn): boolean {
    return this.value === other.value;
  }

  toString(): string {
    return this.value;
  }
}

function errorResponse(error: unknown): Response {
  if (error instanceof InvalidInput || error instanceof InvalidValue) {
    return Response.json({ error: error.message }, { status: 400 });
  }

  if (error instanceof NotFound) {
    return Response.json({ error: error.message }, { status: 404 });
  }

  if (error instanceof RuleConflict || error instanceof DomainError) {
    return Response.json({ error: error.message }, { status: 409 });
  }

  console.error(error);

  return Response.json({ error: "Erro interno" }, { status: 500 });
}

export function createServer(useCases: UseCases, porta = 3000) {
  const routes: Route[] = [
    {
      method: "GET",
      pattern: "/",
      handler: () => Response.json({ message: "API da Biblioteca" }),
    },
    ...livroRoutes(useCases),
  ];

  return Bun.serve({
    port: porta,

    async fetch(request) {
      const url = new URL(request.url);

      try {
        for (const route of routes) {
          if (route.method !== request.method) continue;

          const params = match(route.pattern, url.pathname);
          if (params) return await route.handler(request, params);
        }

        return Response.json(
          { error: "Recurso não encontrado" },
          { status: 404 },
        );
      } catch (error) {
        return errorResponse(error);
      }
    },
  });
}

    return salvo;
  }

  findByIsbn(isbn: Isbn): Livro | null {
    return this.items.find((item) => item.isbn.equals(isbn)) ?? null;
  }

  findByAutorId(autorId: AutorId): Livro[] {
    return this.items.filter((item) => item.autorId.equals(autorId));
  }

  searchByTitulo(termo: string): Livro[] {
    const alvo = termo.toLowerCase();

    return this.items.filter((item) => item.titulo.toLowerCase().includes(alvo));
  }

  searchByNomeDoAutor(_termo: string): Livro[] {
    // ⚠️ o dublê não sabe responder: esta é uma pergunta sobre AUTORES, e um
    // repositório de livros em memória não tem como conhecê-los. Fase 50.
    throw new Error("searchByNomeDoAutor não tem como ser respondido em memória");
  }
}

export class InMemoryAutorRepository implements AutorRepository {
  constructor(private readonly items: Autor[]) {}

  findById(autorId: AutorId): Autor | null {
    return this.items.find((item) => item.id.equals(autorId)) ?? null;
  }
}

Repare que searchByTitulo em memória usa includes, e no SQLite usa LIKE. Não são a mesma coisa — LIKE do SQLite ignora maiúsculas só para ASCII, includes com toLowerCase() ignora para tudo. Isso é uma diferença real entre o dublê e o adapter, e vale dizer em voz alta: dublê rápido compra velocidade de teste com um pouco de fidelidade. A regra prática é dublar o que o caso de uso decide, não o que o banco sabe fazer.

E repare no método que o dublê se recusa a implementar: searchByNomeDoAutor lança. Não é preguiça — é que um repositório de livros em memória não tem como saber o nome de autor nenhum. A port pede ao acervo uma pergunta que só a base de autores sabe responder, e o dublê é o primeiro a denunciar isso. Anote: a fase 50 tira essa pergunta daqui.

API pública de módulo e verificação automática de fronteira

Você define por onde se entra em cada módulo — e transforma essa regra em algo que falha o build, não em algo combinado na reunião. Cada módulo passa a ter um arquivo de API pública, e importar por dentro dele para de compilar.

👨‍💻 O que você digita

Cada módulo ganha um index.ts (a sua API pública) e um routes.ts (que registra as suas fatias). As quatro importações que furavam a fronteira passam a apontar para ../../autoria — a porta da frente.

E, o mais importante: scripts/check-boundaries.ts, uma fitness function de arquitetura. Ela varre src/modules/** e reprova qualquer import que entre em outro módulo sem ser pelo index.ts.

Acrescente "verificar": "bun scripts/check-boundaries.ts" ao package.json.

typescript
import { Glob } from "bun";
import { dirname, join, normalize } from "node:path";

const problems: string[] = [];

for await (const file of new Glob("src/modules/**/*.ts").scan(".")) {
  const module = file.split("/")[2]!;
  const code = await Bun.file(file).text();

  for (const found of code.matchAll(/from\s+"(\.[^"]+)"/g)) {
    const target = normalize(join(dirname(file), found[1]!));

    if (!target.startsWith("src/modules/")) continue;

    const otherModule = target.split("/")[2]!;
    if (otherModule === module) continue;

    if (target !== `src/modules/${otherModule}`) {
      problems.push(`${file}\n      importa ${target}`);
    }
  }
}

  for (const problema of problems) console.error(`  ${problema}\n`);

Camada anticorrupção entre os módulos

Você faz o acervo parar de depender do vocabulário e das tripas da autoria: cada módulo passa a declarar o que precisa nos seus próprios termos, e a tradução acontece num adaptador na fronteira. É o que vai permitir, na próxima fase, remover a chave estrangeira sem o domínio perceber.

👨‍💻 O que você digita

Quatro peças:

  1. autoria publica um contrato de leitura (ConsultaDeAutores) na sua API pública;
  2. acervo declara, no domínio dele, a port ConsultaDeAutoria — e inventa o próprio vocabulário: "curta" / "ampla", em vez de "literatura" / "didatico";
  3. um adaptador em src/adapters/ faz a ponte e traduz;
  4. o composition root liga tudo.

 * Camada anticorrupção: aqui — e só aqui — o vocabulário da Autoria
 * ("literatura" / "didatico") vira o vocabulário do Acervo
 * ("curta" / "ampla").
 */
export class AutoriaComoConsulta implements ConsultaDeAutoria {
  constructor(private readonly autores: ConsultaDeAutores) {}

  autor(autorId: AutorId): AutorConhecido | null {
    const resumo = this.autores.resumo(autorId);

    if (!resumo) return null;

    return {
      nome: resumo.nome,
      tiragem: resumo.tipo === "didatico" ? "ampla" : "curta",
    };
  }
}

Cada módulo dono das suas tabelas — e o fim da chave estrangeira cruzada

Você leva a fronteira até o banco. Se acervo e autoria são módulos separados, livros.autorId não pode ser chave estrangeira para uma tabela que não é dele — e o JOIN da busca por nome do autor, escrito lá na fase 11, também não pode existir.

👨‍💻 O que você digita

Cada módulo passa a criar o seu próprio schema (modules/<module>/infrastructure/schema.ts), e infrastructure/db.ts fica só com a conexão. O seed da base de autores vai junto, para dentro de autoria — ele sempre foi dado externo.

O schema de acervo inclui uma migração: o SQLite não sabe remover uma constraint, então é preciso recriar a tabela e copiar os dados.

E a fitness function ganha uma segunda checagem: nenhum módulo pode citar uma tabela que não é dele.

⚠️ Não apague o banco antes desta fase. A verificação precisa de um data/biblioteca.sqlite no formato antigo — com a chave estrangeira — para a migração ter o que migrar.

👨‍💻 O que você digita

src/shared/EventBus.ts — arquivo novo

typescript
export type Event = { readonly nome: string };

export type Listener<E extends Event> = (event: E) => void;

/**
 * Barramento in-process: publicar um evento é uma chamada de função. Não há
 * fila, nem rede, nem broker — mas o ACOPLAMENTO já é o de mensageria: quem
 * publica não sabe quem escuta.
 */
export class EventBus {
  private readonly listeners = new Map<string, Listener<never>[]>();

  subscribe<E extends Event>(nome: E["nome"], listener: Listener<E>): void {
    const atuais = this.listeners.get(nome) ?? [];

    this.listeners.set(nome, [...atuais, listener as Listener<never>]);
  }

  publish<E extends Event>(event: E): void {
    for (const listener of this.listeners.get(event.nome) ?? []) {
      (listener as unknown as Listener<E>)(event);
    }
  }
}
